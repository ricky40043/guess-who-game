# 猜人遊戲：地端 Server 自動部署指南

此專案採用：

```text
push main
  → GitHub-hosted runner 執行測試、靜態檢查、Go build、Docker build
  → 全部成功
  → 地端 self-hosted runner 執行 Docker Compose 部署
  → 健康檢查
  → 失敗時自動回滾上一版
```

Pull Request 只會跑 CI，不會碰地端 Server。只有 `main` 的 push 或在 `main` 手動執行 workflow 才會部署。

---

## 一、Server 前置需求

建議環境：Ubuntu 22.04 / 24.04。

### 1. 安裝 Docker

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
```

重新登入後確認：

```bash
docker version
docker compose version
docker info
```

### 2. 先 Clone 專案並準備部署設定

```bash
git clone https://github.com/ricky40043/guess-who-game.git
cd guess-who-game
git fetch origin
git switch agent/initial-game
bash scripts/setup-server.sh
```

腳本會建立：

```text
/opt/guess-who-game/.env
```

預設內容：

```env
BIND_ADDRESS=127.0.0.1
HOST_PORT=20931
```

- `127.0.0.1`：只允許同一台 Server 的 Cloudflare Tunnel / Nginx 存取，較安全。
- `0.0.0.0`：允許區網直接連入；只有需要區網測試時才改。

設定檔權限會設成 `600`。

## 二、安裝 GitHub Actions self-hosted runner

到 GitHub：

```text
Repo → Settings → Actions → Runners → New self-hosted runner
```

選擇 Linux x64，照 GitHub 畫面下載並解壓縮。設定時務必加入部署標籤：

```bash
./config.sh \
  --url https://github.com/ricky40043/guess-who-game \
  --token <GitHub 畫面提供的一次性 token> \
  --labels guess-who-game-deploy
```

安裝成系統服務：

```bash
sudo ./svc.sh install
sudo ./svc.sh start
sudo ./svc.sh status
```

回到 GitHub Runners 頁面，應顯示綠色 `Idle`，並包含：

```text
gues-who-game-deploy
```

正確標籤名稱是：

```text
guess-who-game-deploy
```

### runner 必須能操作 Docker

runner 服務通常使用執行 `config.sh` 的 Linux 帳號。確認該帳號在 docker 群組：

```bash
groups
docker info
```

若沒有：

```bash
sudo usermod -aG docker $USER
sudo ./svc.sh stop
sudo ./svc.sh start
```

> 公開 Repo 不應讓 Pull Request 工作跑在 self-hosted runner。本專案的 PR 測試固定跑 GitHub-hosted runner，地端 runner 只處理 `main` 部署。

## 三、建立對外連線

Docker 預設把服務綁在：

```text
http://127.0.0.1:20931
```

健康端點：

```text
http://127.0.0.1:20931/api/health
```

### Cloudflare Tunnel

在 Cloudflare Tunnel 的 Public Hostname 設定：

| 欄位 | 值 |
|---|---|
| Type | HTTP |
| URL | `localhost:20931` |

Cloudflare 的 WebSockets 必須維持開啟：

```text
Cloudflare Dashboard → Network → WebSockets → On
```

若 `cloudflared` 本身跑在 Docker 且沒有 host network，不能直接使用該容器自己的 `localhost`。可採其中一種：

1. 讓 cloudflared 使用 `network_mode: host`，URL 維持 `localhost:20931`。
2. 把 cloudflared 與 app 放進同一個 Compose network，再改成 `http://app:8080`。

### Nginx

```nginx
location / {
    proxy_pass http://127.0.0.1:20931;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 90s;
}
```

WebSocket 路徑是 `/ws`，不可漏掉 Upgrade headers。

## 四、GitHub 設定

預設部署設定檔位置已是：

```text
/opt/guess-who-game/.env
```

通常不必設定 GitHub Secret。若路徑不同，可新增 Repository Variable：

```text
Settings → Secrets and variables → Actions → Variables
```

名稱：

```text
DEPLOY_ENV_FILE
```

值例如：

```text
/home/ricky/guess-who-game.env
```

## 五、自動部署流程

PR 合併進 `main` 或直接 push：

```bash
git push origin main
```

GitHub Actions 依序執行：

1. `gofmt` 檢查。
2. `go test -race ./...`。
3. `go vet ./...`。
4. Linux production build。
5. Docker image build 驗證。
6. 成功後把 deploy job 派給地端 runner。
7. 保存目前 `guess-who-game:latest` 為 `guess-who-game:rollback`。
8. Server 本機重新 build image。
9. `docker compose up -d` 更新容器。
10. 最多等待 60 秒健康檢查。
11. 成功後清除 dangling images。
12. 失敗則印出日誌並嘗試回滾。

也可從 GitHub Actions 頁面按 `Run workflow` 手動部署，但必須選 `main`。

## 六、部署後檢查

```bash
docker ps --filter name=guess-who-game
docker logs guess-who-game --tail 100
curl http://127.0.0.1:20931/api/health
```

預期健康回應：

```json
{"status":"ok","time":1234567890}
```

看即時日誌：

```bash
docker compose \
  --project-name guess-who-game \
  --env-file /opt/guess-who-game/.env \
  logs -f app
```

手動執行同一套部署腳本：

```bash
DEPLOY_ENV_FILE=/opt/guess-who-game/.env bash scripts/deploy.sh
```

## 七、常見問題

| 狀況 | 原因與處理 |
|---|---|
| deploy 一直排隊 | runner 離線或沒有 `guess-who-game-deploy` 標籤 |
| runner 顯示 Docker permission denied | runner 帳號未加入 docker 群組；加完後重啟 runner service |
| 找不到 `.env` | 在 Server 執行 `bash scripts/setup-server.sh` |
| 網站能開但一直斷線 | Tunnel / Nginx 未正確轉送 WebSocket Upgrade headers |
| 外部連不到但本機 curl 正常 | Tunnel hostname 或 Nginx upstream 指錯；應指向 `127.0.0.1:20931` |
| 新版部署失敗 | Actions 日誌會包含容器狀態與最近 120 行日誌，若存在上一版 image 會自動回滾 |
| Server 重啟後遊戲房間消失 | 房間目前存在記憶體，這是第一版既有限制 |

## 八、更新 runner

self-hosted runner 通常會自動更新。檢查服務：

```bash
sudo ./svc.sh status
```

若要停用部署，先停 runner：

```bash
sudo ./svc.sh stop
```
