# 架構說明

## 核心原則

- 伺服器是遊戲狀態的唯一真相來源，前端不能自行換題或計分。
- 每個房間持有獨立 mutex，所有房間狀態變更都在鎖內完成。
- `Seq` 用來使上一階段殘留的倒數 goroutine 自動失效。
- 遊戲開始後玩家名單鎖定；斷線者保留身分並可用 localStorage session 重連。

## 狀態機

```text
waiting
  -> answering
  -> revealing
  -> guessing
  -> finished
```

## 匿名規則

回答階段結束後，伺服器只建立一次 `playerId <-> 同學 A/B/...` 映射。公布與猜題階段共用同一份映射，不會因重連或切換畫面重新洗牌。

猜題時，每位玩家的匿名代號與本人名稱都會由伺服器標示，前端排除這兩個選項。伺服器仍會再次驗證，避免竄改 WebSocket payload 作弊。

## 擴充界線

目前房間存在單一 Go process 記憶體。未來若要水平擴充，需要加入：

1. Redis 房間狀態或固定黏著連線。
2. Redis Pub/Sub 或 NATS 做跨節點廣播。
3. 分散式鎖或單房間 actor，避免多節點同時推進狀態。
4. 房間閒置清理與服務重啟後的恢復策略。
